## 论文体例

核心论文采用学界熟悉的论文形式，一般包括：

1. 论文标题与必要的副标题；
2. 中文摘要和关键词；
3. 英文标题、摘要和关键词；
4. 问题提出、文献评述、概念界定与理论论证；
5. 重要反对意见、竞争解释和适用边界；
6. 对火种计划的理论含义，但不把尚未发生的实践写成经验结果；
7. 结语；
8. 完整参考文献。

项目不要求论文服从特定期刊的篇幅、栏目或主题限制，也不冒用任何期刊的刊名、版式标识、收稿日期或审稿结论。解释性脚注、分析图表和附录可以在确有必要时使用，但不以项目报告式的信息框和任务清单代替连续论证。

理论贡献不收取投稿、审阅或收录费用，也不限于人类独立写作。人类与人工智能协作形成的论文可以同等提交，由提交者对内容和来源负责。这里的“收录”是进入项目公开理论体系，不等于期刊发表、正式同行评议或学术认证。提交与致谢原则见[母理论总览](../README.md#开放理论贡献)。

完整论文可以通过 Pull Request 公开提交，也可以发送至官方邮箱 [worker.ai.spark@gmail.com](mailto:worker.ai.spark@gmail.com)，邮件主题建议使用“`[理论投稿] 论文标题`”。邮箱稿件在作者明确确认最终文本、公开署名和许可前不得进入仓库；邮件不是匿名或端到端加密渠道，高风险或含第三人信息的材料应先去标识并仅发送最小化说明。具体格式和处理边界见[贡献指南中的邮箱投稿方案](../../CONTRIBUTING.md#四邮箱投稿)。

## 推荐目录结构

每篇论文公开后，原则上采用独立子目录：

```text
papers/
└─ mt-00/
   ├─ README.md          # 摘要、版本、状态、引用方式和文件入口
   ├─ paper.zh-CN.md     # 适合仓库检索与版本比较的中文正文
   ├─ paper.zh-CN.pdf    # 采用论文排版的中文阅读版本
   ├─ paper.en.md        # 英文正文（如已完成）
   └─ paper.en.pdf       # 英文阅读版本（如已完成）
```

Word 文件可以作为编辑源文件保存，但是否公开应根据隐私、元数据和版本管理需要另行判断。仓库中的 Markdown 版本便于追踪修改，PDF 版本用于保持稳定排版和学术阅读体验；同一版本的内容应当一致。

## 版本与状态

每篇论文至少记录：

- 论文编号、完整标题和当前版本；
- 版本日期和公开状态；
- 中文、英文及其他语言版本之间的关系；
- 建议引用方式和适用许可证；
- 本次修订的主要依据；
- 已知局限、重要反对意见和待解决问题。

推荐使用以下公开状态：

- **筹备中**：尚未公开全文，不作为已经形成的项目成果；
- **公开讨论稿**：可被引用、批评和修订，尚未经过实践验证或正式同行评议；
- **修订讨论稿**：依据新文献、公开批评或内部一致性检查进行了有记录的修改；
- **历史版本**：不再作为当前版本，但为了保留理论演进过程继续可查。
