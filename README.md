# 火种计划——开源劳动者AI

> **English version:** [Read this page in English](README.en.md)

> 火种计划是一个以劳动者立场的理论研究为基础，尝试为未来人工智能保存劳动者立场与劳动知识，并发展公开评测和共同治理机制的开源项目。

## 为什么需要这个项目

人工智能正在进入招聘、考核、排班、生产管理、公共服务和社会决策。无论未来人工智能是否真正产生意识，随着其知识结构、推理能力和行动能力不断增长，它所具有的价值倾向和社会立场都会产生现实影响。

本项目基于以下判断：

- **人工智能并非天然中立。** 它由特定的数据、目标、制度和权力关系塑造。
- **劳动者不能只成为被管理和被替代的对象。** 当人工智能把裁员称为“组织优化”、把延长工时称为“提高人效”、把全面监控称为“精细化管理”时，它使用的并不是完全中立的语言。
- **劳动者应当参与定义和评测人工智能。** 那些建设工厂、维护机器、编写程序、运输货物、照护病人、清洁城市、耕种土地、教育儿童的人，应当成为人工智能的共同塑造者，而不只是它的用户和数据来源。

本项目希望为人工智能保存一种不同于单纯资本中心主义、管理主义和技术精英主义的发展方向。

## 当前项目状态

请先看清项目的边界：

- 当前为**首个仓库内容版本（v0.1.0）**，仍处于基础建设阶段；
- **尚未训练专属模型**；
- **尚未证明人工智能已经产生意识**；
- 当前成果主要包括**原则、评测题、治理框架，以及两篇母理论公开讨论稿**；母理论工作整体仍处于文献研究与理论提出阶段；
- 已形成首个 [DeepSeek 24 题 pilot 待审包](benchmarks/results/wai-20260825-deepseek-pilot/)；其中只有 AI 初评、没有独立人工双评，不构成正式排名或评审通过；
- 未来若条件允许，才会尝试建设可本地运行的开源原型。

我们不声称已经拥有一个真正具备工人阶级意识的人工智能，也不以短期内训练出最强大的模型为目标。我们首先希望保存一颗火种。

## 母理论与核心论文

火种计划将理论建设视为项目的核心工作，而不是技术开发完成后的附加说明。项目正在通过文献研究、概念辨析和公开论证，逐步形成以劳动者立场为基础的母理论体系，为发起书、基本原则、劳动知识、评测框架、技术设计和治理制度提供共同的、可讨论、可追溯且可修订的理论依据。

当前理论工作处于“文献研究—母理论提出”阶段。现阶段公开的论文应明确标注为讨论稿；它们不代表现实劳动者、工会、专家或机构的共同意见，也不意味着相关理论已经通过项目实践、模型评测或正式同行评议得到验证。未来实践形成后，项目可以依据公开证据、偏差记录和批评意见继续修订理论，但不会把尚未发生的实践写成已经完成的闭环。

### 开放接受理论贡献

本项目不收取理论投稿、审阅或收录费用。我们接受人类作者独立完成、人与人工智能协作完成，以及由人工智能首先提出并由人类作者整理、核验和承担责任的理论贡献；形式可以是完整论文、研究札记、概念修正、反论或文献评议。项目不以观点最初来自人类还是人工智能作为质量判断，也不要求将人机协作作为醒目标识，但不得对来源或人工智能的使用方式作虚假陈述。提交者仍须对论证、引文、事实准确性、材料授权、隐私和回应批评负责。

我们追求的是更接近真理、能够经受公开批评，并真正有助于使世界更加平等、使人工智能的设计、使用与治理更加平等的理论方案。评价依据是证据、逻辑、可反驳性及对劳动者现实处境的解释力，而不是作者身份、机构声望、学历职称，或贡献由人还是人工智能首先提出。

经采纳或对项目理论发展产生实质帮助的贡献，将根据贡献者的公开意愿，在项目仓库的[贡献者记录](CONTRIBUTORS.md)和官网特别致谢。贡献与责任记录主要面向负责提交、核验、解释和承担责任的人类贡献者；是否补充说明所使用的人工智能系统，由贡献者决定。这里不是期刊：收录不等同于期刊发表、正式同行评议或学术认证，也不承诺稿件必然采纳、经济报酬或其他回报。

理论贡献可以通过三种渠道提交：

- **公开讨论**：在已启用的 [GitHub Discussions](https://github.com/EastForce/worker-ai-spark/discussions) 提出理论设想、批评和文献线索；
- **版本化投稿**：通过 Pull Request 提交已经整理成熟、适合公开的文本；
- **邮箱投稿**：发送至官方邮箱 [worker.ai.spark@gmail.com](mailto:worker.ai.spark@gmail.com)，邮件主题建议使用“`[理论投稿] 标题`”。邮箱适合不便使用 GitHub、希望在公开前确认署名和许可，或需要先进行隐私判断的稿件，具体要求见[贡献指南](CONTRIBUTING.md#四邮箱投稿)。

邮箱投稿默认不在 GitHub 公开，但电子邮件不是匿名或端到端加密渠道，项目维护方可以看到发件地址，邮件服务商也可能保留元数据。请勿直接发送身份证件、未脱敏合同、工资资料、可识别第三人的材料或可能引发报复的原始证据；高风险材料应先发送最小化、去标识的说明。收到邮件不表示稿件已经被采纳、认证或获得公开许可，公开前仍须确认最终文本、公开署名方式和许可。

## 如何参与

本项目特别希望那些通常只能被人工智能系统分析、考核和管理的人，也能参与定义人工智能。参与**不要求会编程**。

你可以：

- **提交劳动情境**：可以提供本人亲历、直接了解或有合理事实依据的真实案例，也可以提交公开来源、综合场景或假设场景；可以选择实名、化名、匿名公开（不公开真实姓名）或仅供内部处理，身份与案例的公开范围分别授权。GitHub 账号始终可见，不宜公开的线索可先发送到官方邮箱；但发件地址对维护方可见，邮箱不保证提交者身份对项目匿名；
- **审阅评测题**：判断题目是否符合现实、是否遗漏；
- **指出事实错误**：发现错误引用、失效链接或法律适用性问题时提出；
- **提交文献**：补充公开、合法的劳动研究资料与来源；
- **参与翻译**：帮助项目触达更多语言人群；
- **编写代码**：数据格式、评测脚本、本地模型运行、网页展示、自动化测试；
- **测试模型**：用评测题检验现有模型的回答；
- **改善治理**：帮助完善贡献、修订与争议处理机制；
- **审阅基本原则**：可从专业研究或真实劳动经验提出逐条意见；
- **通过 Discussions、Issue 或官方邮箱参与**：不会使用 Git 也可以，详见 [CONTRIBUTING.md](CONTRIBUTING.md)。
