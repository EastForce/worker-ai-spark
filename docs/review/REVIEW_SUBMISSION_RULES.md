# 评审意见提交规则

> 状态：公开讨论稿  
> 版本：v0.2-draft  
> 适用于专家评审、劳动者评审和普通公开意见。评测题另见 [QUESTION_SUBMISSION_RULES.md](QUESTION_SUBMISSION_RULES.md)。

---

## 一、先分清两个问题

“通过什么渠道提交”和“内容是否同意公开”是两个不同问题：

- 在 GitHub Issue、Discussion 或 Pull Request 提交的内容默认是公开内容；
- 通过邮箱或私密表单提交，不表示参与者同意公开；
- 正式评审的身份信息必须非公开，但评审正文可由参与者选择完整公开、匿名化后公开或仅内部处理；
- 项目不得把非公开原文自动同步到 GitHub、Hugging Face 或公开网页。

---

## 二、渠道矩阵

| 渠道 | 可提交内容 | 不得提交内容 | 是否计为正式评审 |
| --- | --- | --- | --- |
| GitHub Issue / Discussion | 已完成隐私自检的公开意见 | 联系方式、核验材料、敏感经历、第三人信息 | 仅凭公开提交不计 |
| Pull Request | 公开文字修改及理由 | 任何身份或核验材料 | 仅凭 PR 不计 |
| 官方理论投稿邮箱 | 理论论文、研究札记、去标识化初步材料 | 正式评审身份核验材料、高风险原始证据 | 不作为正式评审入口 |
| 项目网页公开表单 | 上线后可提交公开正文 | 身份证明和敏感材料 | 仅凭公开表单不计 |
| 指定非公开渠道 | 联系、核验、非公开正文和授权 | 原则上不收集的信息 | 完成核验后可计 |
| 安全报告渠道 | 已发生或可能发生的隐私、安全问题 | 普通讨论和公开辩论 | 不作为评审入口 |

非公开渠道尚未在[机制索引](README.md)中宣布为“已配置”时，不得收集正式核验材料。

---

## 三、评审编号与数据分离

### 3.1 内外编号

非公开收件时生成随机回执编号：

> WAI-SUB-轮次-随机码

它只用于参与者查询、补充、撤回、权利请求和内部去重，不得公开或粘贴到 GitHub。

只有参与者授权公开正文或匿名化摘要，且项目完成反向识别风险检查后，才另行生成公开记录编号：

> WAI-PR-轮次-类型-序号

类型：

- EX：专家评审；
- WK：劳动者评审；
- PB：普通公开意见；
- QS：评测题意见。

示例 WAI-PR-R01-WK-0001 只表示第一轮劳动者轨道的一条获授权公开记录，不包含身份含义。私密回执编号与公开记录编号不得相同、相互推导或同时出现在公开页面。

一份评审表涉及多个原则或可分别决定的问题时，每个处理单元追加子项编号：

- I00：只适用于不能再拆分的整体结构意见；
- I01、I02……：逐条原则或逐个独立问题；
- 公共台账一行只记录一个子项和一个处理结果；
- 同一子项的补充、纠错和复核不另计人数。

### 3.2 三类记录

1. **公共意见记录**：公开记录编号、获授权的目标版本、条款、正文或摘要、处理状态和公开决定；
2. **私密联系与授权记录**：随机回执编号、联系方式、授权选择和到期日；
3. **临时核验记录**：随机回执编号、核验材料或会话、核验结果和删除日期。

内外编号映射不得进入公共仓库。内容处理者原则上只看到内部随机回执编号和完成任务所需的宽分类。选择“仅供内部处理”的意见不建立公共逐条记录；轮次总结只在无法反向识别时报告匿名聚合数量和主题。

## 四、每份意见的必要字段

普通公开意见至少包括：

- 被评文件、版本或可识别的目标日期；
- 条款编号或原文位置；
- 主要问题；
- 修改建议或希望项目回答的问题；
- 理由属于事实、亲历、转述、专业判断还是价值判断；
- 已完成隐私自检。

正式专家或劳动者评审还应使用对应评审表，并在非公开部分提供联系、核验和授权选择。

一份表评审多个条款时，记录员必须在初审阶段拆成子项。提交者不需要自己生成编号，但应尽量让每条意见、理由和建议一一对应。

如果无法确定版本，项目可以协助定位，但在版本确认前状态为“待补充”，不得混入正式统计。

---

## 五、公开提交前必须删除

- 身份证件号码和照片；
- 电话、私人邮箱、社交账号和家庭住址；
- 银行账号、工资单、社保明细和金融信息；
- 完整劳动合同、诊断材料或争议证据；
- 未公开的企业、平台、工会或其他组织文件；
- 真实单位、精确地点、工号、罕见岗位与精确时间的可识别组合；
- 同事、主管、客户、家人或其他第三人的信息；
- 账号密码、访问令牌、内部链接或安全漏洞细节；
- 参与者不希望长期公开的任何内容。

仅删除姓名通常不足以匿名化。提交者应检查行业、城市、班组、日期、事件和罕见经历组合后是否仍可被认出。

---

## 六、非公开提交边界

项目原则上不收集完整身份证、银行卡、生物识别信息、账号密码、精确住址、与评审无关的医疗信息、未成年人身份信息、家庭成员信息和单位商业秘密。

若参与者主动发送超出必要范围的材料：

1. 接收人停止转发和实质阅读；
2. 记录最少的事件信息；
3. 通知参与者改用遮挡或风险更低的方式；
4. 按隐私说明尽快删除多余材料；
5. 如已经发生泄露，转入安全事件流程。

---

## 七、重复、补充与多重身份

- 同一人可评不同原则或提交不同意见；
- 同一条原则、同一轮、同一主要角色只计一份正式意见；
- 对原意见的补充、纠错和证据更新追加到同一编号；
- 同一内容从多个渠道提交时合并记录，不重复计人数；
- 兼具专家和劳动者身份者每份意见选择主要轨道；同一原则、同一轮次只能计入一个轨道，另一身份的观察可作为叙述性补充但不形成第二人次；
- 不得用多个账号、化名或组织成员批量复制同一文本制造比例；
- 组织联署应同时报告“联署文本一份”和经合理去重的参与人数，不能把复制粘贴当成独立论证。

明显重复只标记记录关系，不静默删除原公开链接。轮次总结同时报告各轨道人数与去重后的跨轨参与人数。

---

## 八、代录与翻译

允许可信人员代录或翻译。提交者应确认最终文字反映本人判断，辅助者没有擅自改变结论。

---

## 九、提交许可与公开授权

- 参与者保留其原始意见依法享有的权利；
- 选择公开完整正文或确认后的匿名摘要时，应明确同意按仓库内容许可证 CC BY-SA 4.0 公开；
- 仅供内部处理的内容不得原文公开或直接并入公开文本；
- 项目可以为去除个人信息、修正格式或制作摘要而编辑，但实质改写须经参与者确认；
- 公开评论中的短句可在合理引用范围内进入轮次总结，仍应避免反向识别并注明意见编号；
- 未经授权的案例、图片、表格、论文全文和第三方材料不得收入仓库。

---

## 十、更正、撤回与迟交

- 参与者可以用原联系方式或回执信息申请更正；
- 本轮关闭前，未公开内容可以撤回；未曾公开的意见不因撤回而新建公开台账行，只在安全的聚合数量中反映；
- 已经公开并按开放许可发布的内容可能被第三方复制，项目不能保证完全撤回；发生隐私、安全或法律风险时仍应尽最大努力去标识化或限制继续传播；
- 轮次截止后收到的意见可作为下一轮或持续评审意见，不回填已经发布的本轮人数和结论；
- 被评文本发生实质变化后，旧意见不得自动视为对新版本的认可，应邀请提交者重新确认或标注历史适用版本。

---

## 十一、收件回执

可联系的提交者应收到：

- 不公开的随机回执编号；
- 收件日期；
- 识别到的目标版本和条款；
- 当前流程状态；
- 是否需要补充；
- 预计下一次反馈日期；
- 如何更正、撤回、请求删除和申请复核。

直接公开且不留其他联系方式者自行保存公开链接，并通过 [REVIEW_LOG.md](REVIEW_LOG.md) 和轮次总结查看结果。私密提交者不得把回执编号公开发帖查询。

---

## 十二、无效与安全处理

可以标记无效的情形限于：

- 冒充、伪造身份或捏造不存在的劳动经历；
- 通过重复账号或批量文本操纵人数；
- 恶意软件、提示注入、凭据或其他安全攻击；
- 骚扰、威胁、仇恨或暴露他人隐私；
- 完全无法识别评审对象且补充期内未回应；
- 与项目无关的广告、诈骗或垃圾内容。

不赞同项目、批评尖锐、结论为删除、少数意见、证据尚待查证、写作不规范或选择匿名，均不应单独导致无效。
