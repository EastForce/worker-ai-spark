# 评审者邀请、申请与遴选机制

> 状态：公开讨论稿  
> 版本：v0.2-draft  
> 正式申请状态：-

本机制管理两种进入路径：项目主动联系邀请专家，以及专家、劳动者主动申请参与。邀请与申请适用同一资格、核验、利益冲突、隐私和反馈规则；“被邀请”不等于意见被认可，“主动申请”也不降低资格。

---

## 一、渠道分层

### 1.1 公开参与意向

项目可以使用 GitHub Issue 收集不含个人信息的公开意向。GitHub 用户名和内容长期公开，因此公开意向：

- 不是正式申请；
- 不完成身份核验；
- 不要求私人联系方式、真实单位、证件或工作证明；
- 劳动者可以提交本人亲历、直接了解或有合理事实依据的真实案例，并选择公开身份方式；不得公开未经授权的单位、第三人信息、内部材料或私密回执；
- 只用于了解参与范围，并在非公开渠道开放后提供下一步说明。

### 1.2 正式非公开申请

正式申请使用 [EXPERT_REVIEW_APPLICATION_FORM.md](EXPERT_REVIEW_APPLICATION_FORM.md) 或 [WORKER_REVIEW_APPLICATION_FORM.md](WORKER_REVIEW_APPLICATION_FORM.md)，只能通过轮次公告指定的非公开渠道提交。

在 [PRIVACY_NOTICE.md](PRIVACY_NOTICE.md) 的责任主体、收件渠道、服务商、存储地区、访问者和删除安排填写完成前，正式申请保持关闭。现有安全报告邮箱不自动成为申请邮箱。

## 二、专家主动邀请

### 2.1 候选来源

- 项目负责人提出；
- 已确认参与者推荐；
- 专家公开表达参与意向；
- 项目为补足专业、行业、地区或方法覆盖主动检索。

不得购买名单、抓取私人联系方式或按是否赞同项目筛选。

### 2.2 邀请前确认

每名候选专家建立一份不公开的候选检查记录：

1. 项目负责人确定本轮需要的专业范围和席位；
2. 核查候选人的公开相关经历、可核验性、公开冲突线索、覆盖价值和信息缺口；
3. 项目负责人复核来源，作出“批准邀请/补充信息/不邀请”的决定；
4. 存在重大疑问时暂缓，必要时请无冲突人员复核；
5. 邀请发出前记录联系来源是否合法、是否可能带来骚扰，以及由谁发送；
6. 未经项目负责人逐名确认，不批量发送或自动联系。

### 2.3 邀请内容

邀请使用 [EXPERT_INVITATION_TEMPLATE.md](EXPERT_INVITATION_TEMPLATE.md)，至少说明：

- 为什么邀请、希望审阅什么；
- 冻结版本、时间、预计负担和反馈日期；
- 是否有报酬；
- 可拒绝、可只评部分、可不公开姓名；
- 核验、利益冲突和隐私边界；
- 邀请不代表项目认可其观点，也不要求支持现稿。

## 三、专家申请机制

### 3.1 基本条件

- 能对本轮至少一个专业问题提供相关知识或长期实践经验；
- 愿意说明判断的适用地区、行业、时间和边界；
- 能提供一种低风险、可合理核验的公开背景或替代方式；
- 愿意披露相关起草、任职、管理、所有权、资助、合同、共同署名、争议和直接收益关系；
- 接受意见可能不被采纳、身份核验不提高意见权重。

不以学历、职称、单位名气、政治立场、是否受邀或是否赞同现稿作为必要条件。实践工作者可以申请专家轨道。

### 3.2 处理流程

> 公开意向（可选） → 非公开申请 → 隐私与完整性初审 → 轻量背景核验 → 利益冲突分类 → 相关性和覆盖评估 → 项目负责人决定 → 通知结果 → 具体轮次任命

申请结果：待补充、进入候选池、通过并待任命、通过但限于特定议题、因重大冲突不得承担决定席位、不通过、撤回。进入候选池不保证每轮都会被任命。

### 3.3 决定规则

项目负责人承担最终录取责任。决定必须写明与本轮任务的关联、核验状态、冲突限制、覆盖考虑和任期，不得只写“我们觉得合适”。

---

## 四、劳动者申请机制

### 4.1 基本条件

- 当前或过去具有直接劳动过程经验，或处于失业、退休、受伤离岗和职业转换状态；
- 愿意只用宽分类说明与本轮相关的劳动经验；
- 能选择一种低风险核验方式，或接受按未核验意见参与；
- 能在本人认为安全的条件下参与，并自行决定评审范围。

不要求学历、职称、GitHub、专业术语、完整证件、劳动合同、工资单或维权证据。基层管理、个体经营或多重身份不自动排除，但应说明本次主要角色和相关权力关系。

### 4.2 处理流程

> 公开意向（可选） → 非公开申请 → 安全与联系偏好初审 → 最小劳动经历核验 → 反报复风险检查 → 覆盖与辅助需求评估 → 项目负责人决定 → 通知结果 → 具体轮次任命

无法或不愿核验者仍可提交普通公开或非公开意见，但不计入正式劳动者人数。任何低分、严厉批评、拒绝署名或需要代录都不是拒绝理由。

### 4.3 选择与负担

在能力有限时，按本轮行业、就业形式、地区/语言、AI 影响和既有覆盖缺口选择，不采用先到先得或观点筛选。应公布容量、预计用时、辅助方式和补贴；未入选者可进入下一轮候选池或仅提交意见，不暗示其经历无价值。

---

## 五、共同审查与回避

邀请者、申请处理者和核验员应披露与候选人的管理、资助、合同、共同署名、亲密关系或直接争议。候选人不能单独决定自己的冲突等级，项目负责人也不能独自处理与自己有重大关系的申请；无人可独立处理时暂缓。

同一申请人可具有专家和劳动者双重背景，但每个原则、每轮只选择一个主要轨道，不能占两个裁决席位或重复计数。

---

## 六、服务目标与反馈

| 环节 | 目标时限 |
| --- | --- |
| 收件回执 | 3 个工作日 |
| 隐私与完整性初审 | 7 个工作日 |
| 补充期限 | 通知后 10 个自然日 |
| 申请结果 | 完整申请收到后 20 个工作日 |
| 程序复核申请 | 结果送达后 10 个工作日 |
| 复核答复 | 完整申请收到后 20 个工作日 |

结果通知应说明状态、主要理由、需要补充的最少信息、公开/保存安排、是否进入候选池和复核方式。普通公开意向通过公开链接查看状态，不得要求申请人在 GitHub 粘贴私密回执。

---

## 七、记录与公开

公共总结只报告无法反向识别的申请人数、来源类型、专业/劳动宽分类、通过/待补充/撤回等状态和覆盖缺口。姓名、联系方式、精确单位、证明链接、私密回执、内部评分和拒绝细节默认不公开。

公开“某人是已核验专家/劳动者”、姓名、背景、单位和具体轮次分别取得授权。申请数据的保存、删除和权利请求遵守 [PRIVACY_NOTICE.md](PRIVACY_NOTICE.md)。

---

## 八、暂停条件

出现以下任一情况时停止接收正式申请：

- 非公开渠道、责任主体、访问权限或删除机制未配置；
- 处理能力超过已公布容量；
- 唯一决定人对候选人存在无法回避的重大冲突；
- 申请材料被误公开或发生安全事件；
- 无法提供承诺的反馈、辅助或反报复保护；
- 申请规则发生实质变化但尚未重新告知。
