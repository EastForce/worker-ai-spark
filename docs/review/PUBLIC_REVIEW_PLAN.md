## 一、目的与边界

《劳动者AI基本原则》目前是早期草案。公开评审的目的不是邀请若干人员为项目背书，也不是用一次投票宣布原则已经代表广大劳动者，而是建立一套公开、可追踪、允许异议并能持续修订的检验机制。

本方案要形成以下闭环：

> 冻结被评版本 → 专家审阅 → 劳动者检验 → 公开反馈 → 理由化决定 → 修改原则 → 共建评测题 → 多模型试测 → 公开结果与局限 → 再次修订

本阶段优先完成制度与小范围流程试评审。当前仓库只建立网页入口和 Hugging Face 评测样板的验收条件与可复现协议；实际服务、账户、数据集仓库和公开链接应在制度运行稳定且另经项目确认后建设，不在本方案中虚构已经上线的服务。

## 二、基本原则

### 2.1 公开与可追踪

原则版本、评审规则、匿名化后的处理结果、主要争议和修改记录原则上公开。项目不仅记录支持意见，也记录具有代表性的反对、保留和未解决意见。

### 2.2 劳动者主体

劳动者是原则和评测机制的共同制定者。专家可以检验理论、事实、法律、伦理和技术质量，但不能代替劳动者判断场景是否真实、语言是否可理解以及风险由谁承担。

### 2.3 专业审查

相关领域专家检验概念、证据、内部一致性、可执行性、可评测性和潜在滥用。专业身份不使意见自动正确；论证仍须接受质疑。

### 2.4 不垄断解释权

发起人对初期维护承担责任，但任何发起人、专家、劳动者、机构或模型都不是不可质疑的最终权威。

### 2.5 多轮修订

评审不是一次性公投。每一轮都应公布目标、实际覆盖、局限和下一步，不以简单多数表决替代理由判断。

### 2.6 隐私与安全

公开正文与非公开身份材料分离，只收集实现联系和必要核验所需的最少信息。任何证件、联系方式、未匿名化劳动争议和单位内部材料均不得进入公开仓库。

### 2.7 无障碍与低门槛

参与不以会使用 GitHub、掌握专业术语或具备正式学历为前提。每轮正式开放前，至少应提供一种不依赖 GitHub、可低带宽使用或由项目辅助录入的入口，并公布通俗文本和可用辅助方式；辅助者不得替代参与者作出判断。没有安全、可实际使用的非 GitHub 入口时，不得宣布正式评审已经开放。

### 2.8 反报复与不歧视

不得因参与者提出批评、选择匿名、拒绝非必要核验、撤回同意或使用辅助方式而给予不利对待。发现可能导致劳动报复或身份暴露的材料时，应优先停止公开和降低识别风险。

## 三、评审对象与冻结

每轮开始前，评审协调人必须发布轮次公告并记录：

- 被评文件名和公开链接；
- 文本版本号；
- Git commit；
- 文件 SHA-256；
- 评审范围和不在本轮处理的范围；
- 起止日期、预计反馈日期和时区；
- 本轮目标专业领域、行业与就业形式；
- 参与入口和隐私说明版本；
- 本轮负责人、核验角色和决定责任人；
- 上一版本的未决争议。

评审期间原则正文如发生紧急修正，应停止受影响条目的收件，公布变更原因并重新冻结版本。不同目标版本的意见不得不加说明地合并。

## 四、参与层级

| 层级 | 类型 | 最低要求 | 公开统计方式 |
| --- | --- | --- | --- |
| 一级 | 普通公开、化名或非公开意见 | 无需身份核验；公开渠道不得包含敏感信息 | 未核验公开意见；非公开意见只作安全聚合 |
| 二级 | 正式劳动者评审 | 联系方式、劳动经历说明、轻量核验、用途同意 | 正式核验劳动者 |
| 三级 | 正式专家评审 | 联系方式、专业经历、背景核验、利益冲突声明 | 正式核验专家 |
| 四级 | 自愿公开署名 | 已完成二级或三级核验，并逐项授权公开 | 署名评审者 |

身份核验只确认申报类别基本可信，不提高意见权重，不表示其代表某一群体，也不表示项目认可其观点。

同一参与者兼具多种身份时，应为每一份意见选择一个主要评审角色。同一人、同一原则、同一轮次只计入一个主要轨道；其另一身份的不同视角可以作为叙述性补充，但不作为第二名参与者或第二个轨道人数。轮次总结应报告跨轨参与的去重人数。

## 五、多轮安排

### 5.1 第一轮：流程试评审

目标是检验表格是否清晰、原则是否易懂、公开与非公开渠道是否真正分离、核验是否过重、反馈能否按时完成，并发现明显缺失和歧义。

第一轮不追求样本数量，不声称具备广泛代表性。完成条件是：

- 已处理本轮截止前收到的有效意见；
- 已公开实际参与构成和覆盖缺口；
- 已完成隐私与流程复盘；
- 已发布逐项决定或明确的暂缓理由；
- 已形成至少一个可检查的小范围修订版本，并公开修改前后差异和决定记录；如果本轮没有修改，也应逐项说明理由；
- 已建立下一轮修订清单。

### 5.2 第二轮：定向邀请评审

重点邀请人工智能、算法治理、劳动关系、工会研究、劳动法、社会保障、社会学、政治经济学、职业健康与安全等领域，以及工厂、平台、服务、照护、物流、建筑、灵活就业、失业、退休和职业转换等不同劳动经历的参与者。

本轮重点检验跨行业、跨劳动关系和跨就业形式的适用性。轮次总结必须披露仍未覆盖的群体，不得用少量参与者推断整体意见。

第二轮起，拟称为“完成双轨评审”或“可作为稳定文本使用”的条款，必须由至少两名具有相关经历的正式劳动者和两名相关正式专家完成独立审阅，并按[治理、角色与回避规则](GOVERNANCE_AND_ROLES.md)进入五人裁决评审组。人数、轨道或独立性不足时，只能标为“证据不足”“争议未决”或“维护者草案”，没有例外豁免。

### 5.3 第三轮：公开征集评审

通过 GitHub、上线后的项目网页及其他已公开渠道征集意见。未受定向邀请者可以提交普通公开意见、申请正式专家或劳动者评审、投稿评测题，或提供技术、翻译和治理建议。劳动者可以提交本人亲历、直接了解或有合理事实依据的真实案例，并选择实名、化名、匿名或仅供内部处理；身份、单位、联系方式、原始材料和正文分别授权。需要隐藏账号、含可识别第三人或可能导致报复的线索只能使用轮次公告指定的非公开渠道。任何公开入口都不得被描述为匿名入口。

### 5.4 后续轮次：持续评审

原则发生重大修改、出现新 AI 场景或劳动风险、重要争议长期无法处理、评测实践发现原则不可检验，或参与者提出具有重大意义的新问题时，可以启动新一轮。

### 5.5 成熟度与覆盖门槛

评分、参与人数和点赞只能触发进一步审查，不能自动决定采纳或“通过”。第二轮及以后，每个拟标记为稳定的实质条款必须分别报告劳动者轨道和专家轨道的有效人数、缺失、回避和异议；任一轨道少于两名相关独立正式评审者，仍存在未解除的重大风险，或任一独立轨道评审者提出的事实、基本权利、安全、严重伤害或关键适用范围异议尚未回应时，不得标为稳定。完成四人双轨审阅但仍有实质分歧时，只能标为“完成双轨评审—争议未决”。该门槛不表示样本具有统计代表性，也不允许把少量参与者称为整个群体的共同意见。

## 六、标准工作流

1. **准备**：完成开放条件，冻结版本并发布轮次公告；
2. **收件**：生成不公开的随机回执编号；只有获得公开授权后才另行生成公开记录编号；
3. **隐私预检**：先检查公开正文是否含敏感信息或第三人信息；
4. **格式审查**：判断范围、完整性、重复情况和是否需要补充；
5. **身份核验**：仅对申请正式身份者使用非公开渠道开展轻量核验；
6. **分轨整理**：专家、劳动者和普通公开意见分别记录；
7. **分析与澄清**：按事实、影响、风险、覆盖、一致性和可检验性分析，必要时请求补充；
8. **拟定决定**：给出处理结果、理由、拟修改位置和未决问题；
9. **回避与复核**：检查利益冲突；重大争议按本制度复核；
10. **个别反馈**：向可联系的正式评审者发送决定或进度说明；
11. **公开总结**：发布匿名化台账、分轨总结、代表性异议和覆盖局限；
12. **修订与留痕**：通过 Pull Request 修改核心文件，并更新决定日志；
13. **到期删除**：执行核验材料和联系方式的删除计划；
14. **复盘**：修订表格、规则和下一轮覆盖目标。

## 七、判断框架

评审结论不得仅由票数决定。处理者至少应回答：

- 意见依赖的事实、法律或研究依据是否可靠，适用时间和地区是什么；
- 对劳动者可能产生何种帮助、成本和严重伤害；
- 是否存在少数群体承担重大风险而被总体平均掩盖；
- 劳动场景是否真实，是否混淆管理者便利与劳动者利益；
- 是否与其他原则冲突，冲突时如何适用；
- 能否转化为明确的 AI 行为要求和可重复评测；
- 是否可能被企业、平台、政府、项目维护者或其他权力主体滥用；
- 是否有风险更低、表达更清楚的替代方案。

事实错误不能因为多数支持而保留；低频但可能造成严重伤害的意见不能因为人数少而忽略；单个真实经验可以揭示问题，但不能未经验证扩展为全体结论。

## 八、专家与劳动者意见的关系

- 专家意见用于检验专业质量，不替代场景真实性判断；
- 劳动者意见用于检验可理解性、现实性与影响，不要求先转化为学术论证才可被记录；
- 两类意见分别汇总，不形成统一总分；
- 专家认可但劳动者认为难懂或脱离现实的，应重新修改表达或适用说明；
- 劳动者提出重大问题但专业依据不足的，应继续邀请相关专家分析，而不是忽略；
- 两类意见冲突时，公开冲突、依据、受影响群体和暂定处理，不伪造共识。

## 九、处理时限

以下为正常情况下的服务目标；志愿维护能力不足时，应提前公告暂停或延迟：

| 环节 | 目标时限 |
| --- | --- |
| 收件回执与编号 | 3 个工作日内 |
| 隐私与完整性初审 | 7 个工作日内 |
| 补充材料期限 | 通知后 10 个自然日 |
| 长期处理中进度更新 | 每 15 个工作日至少一次 |
| 正式意见个别反馈 | 本轮结束后 30 个工作日内 |
| 轮次公开总结 | 个别反馈完成后 15 个工作日内 |
| 复核申请 | 决定送达或公布后 10 个工作日内 |
| 复核答复 | 收到完整申请后 20 个工作日内 |

需要延期时，必须记录原因、新日期和临时风险控制。匿名且没有回执方式的参与者通过公开台账和轮次总结查看结果。

## 十、暂停与升级

出现以下情况时，协调人应暂停相关收件或公开：

- 非公开渠道、访问权限或删除机制尚未就绪；
- 公开内容出现身份信息、商业秘密或可能引发报复的细节；
- 评审目标版本不清或评审期间发生实质变化；
- 唯一决定人存在无法回避的重大利益冲突；
- 出现批量冒充、重复操纵、骚扰或安全事件；
- 现有能力无法安全处理敏感材料；
- 法律、伦理或重大人身风险需要专业处理。

隐私与安全事件按 [SECURITY.md](../../SECURITY.md) 处理；不在公开 Issue 中讨论未修复细节。

## 十一、公开产出

每轮原则上公开：

- 被评版本、时间和实际流程；
- 正式核验专家、正式核验劳动者、未核验公开意见、未核验非公开意见、无效或重复提交的互斥主分类数量；署名、化名、正文不署名和仅内部处理只作为非加总属性另行报告；
- 匿名化后的专业与劳动类型分布；
- 专家意见与劳动者意见的独立总结；
- 已采纳、部分采纳、未采纳、暂缓和未决争议；
- 修改前后差异、理由、依据和适用版本；
- 样本、渠道、地区、语言、行业和方法局限；
- 下一轮计划。

访问量、点赞、转发和简单留言不计为正式评审人数。

---

## 十二、制度变更

本方案自身也是草案。实质性修改应说明修改内容、原因、依据、未采纳意见、尚存争议和生效版本。若修改影响已经提交的个人信息用途、公开范围或保存期限，应在继续处理前重新告知并在依法需要时重新取得同意。

## 十三、后续网页与 Hugging Face 验收条件

### 13.1 网页入口

网页只有同时满足下列条件，才可在仓库中标记为“已上线”：

- 不要求 GitHub 账号，能在低带宽和移动设备上完成基本参与；
- 公开意见、非公开正文、身份核验和安全报告使用清楚分离的入口；
- 表单前显示实际责任主体、服务商、存储地区、用途、期限、权利请求和风险提示；
- 支持只评单条原则、保存草稿、辅助填写和可访问性检查；
- 提交成功后提供私密回执，并能查询、更正、撤回或请求删除；
- 已完成误传敏感信息、权限、备份和到期删除测试。

最低功能清单应包括：项目介绍、原则阅读、劳动者评审、专家评审、候选评测题、真实案例的非公开线索入口、普通公开意见、非公开/正文不署名意见、评审进度、历史版本、意见与题目处理记录、联系项目和隐私说明。各入口可以分期上线，但未上线的模块应明确标记，不得用一个公开表单混收所有内容。

第一阶段明确不建设复杂论坛、积分或排名系统、实名社区、自动身份认证或自动评审裁决。未来新增这些功能前，应重新评估必要性、歧视风险、数据范围和劳动者参与负担。

未满足时，项目只公开“计划建设”，不发布虚构链接或收集身份材料。

### 13.2 Hugging Face 或等效公开评测样板

公开数据集或评测样板只有同时满足下列条件，才可标记为“可复现样板”：

- 机器可读题目通过适用 schema 校验，并保留稳定题号和候选题决定映射；
- 题目、原则、评分规则、模型、提示、参数、日期和原始回答均可追踪；
- 新题完成规定的劳动者场景核验、专家与评分逻辑审查和公开许可；
- 至少两名人工评分者的独立评分、缺失值、分歧、复核和重大风险单独记录；
- 数据卡明确样本、语言、法域、隐私、许可和不能作“最终立场认定”的局限；
- 外部平台账户和发布动作另经项目负责人检查确认。

具体运行要求见 [benchmarks/evaluation-protocol.md](../../benchmarks/evaluation-protocol.md)。

## 十四、项目声明

本项目不声称现有原则代表整个工人阶级，也不声称少量专家或劳动者评审能赋予原则最终权威。公开评审的价值在于让原则持续接受劳动经验、专业研究、技术实践和社会讨论的检验。
