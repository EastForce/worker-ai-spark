# 《劳动者AI基本原则》劳动者评审规则

> 状态：公开讨论稿  
> 版本：v0.2-draft  
> 正式评审尚未开放。参与不要求会编程、会使用 GitHub、拥有正式学历或熟悉理论术语。

---

## 一、劳动者评审的作用

劳动者评审用于判断原则是否听得懂、是否符合真实劳动过程、是否能帮助劳动者、是否遗漏重要问题，以及是否可能被管理者或其他权力主体反向利用。

劳动者不是被研究、被代表或被教育的对象。个人可以只评与自己经历相关的条款，也可以提出不同于项目现稿、专家或其他劳动者的意见。

---

## 二、谁可以参与

本规则中的劳动者包括当前或过去主要依靠劳动获得生活来源的人，例如：

- 工厂工人、基层工程师、司机、配送员、店员；
- 医护、照护、教育、清洁和公共服务人员；
- 平台劳动者、派遣工、临时工、农民工、灵活就业者；
- 对单一平台或发包方具有明显经济依赖的个体经营者；
- 失业、退休、受伤离岗或正在职业转换、但具有相关劳动经历的人；
- 其他具有直接劳动过程经验的人。

承担基层管理职责或同时经营小规模业务的人不因此自动被排除，但应说明本次意见主要基于哪种经历。正式评审者每份意见选择一个主要角色，避免重复计数。

当前阶段不主动招募未满 18 周岁者参加需要身份核验的正式评审，也不收集未成年人的身份材料。未成年人可在监护和安全条件合适时提交不含身份信息的普通公开意见；项目建立专门保护规则前，不计为正式评审。

---

## 三、参与层级

### 3.1 普通公开、非公开或正文不署名意见

任何人都可以不核验身份提交意见。GitHub 用户名不等于真正匿名；非公开或希望正文不显示账号的意见只能在轮次公告指定的非公开渠道开放后提交。未核验意见可以推动修改，但只统计为未核验公开意见或安全聚合的未核验非公开意见。

### 3.2 正式劳动者评审

申请正式劳动者评审者应：

1. 留下至少一种非公开联系方式；
2. 简单说明当前或过去的行业、劳动类型和经历；
3. 选择一种低风险方式支持该经历；
4. 同意信息只用于联系、类别确认、去重和评审处理。

申请流程和遴选规则见 [REVIEWER_RECRUITMENT_AND_SELECTION.md](REVIEWER_RECRUITMENT_AND_SELECTION.md)，正式私密申请使用 [WORKER_REVIEW_APPLICATION_FORM.md](WORKER_REVIEW_APPLICATION_FORM.md)。公开“劳动者评审参与意向”Issue 只登记可公开意向，不是正式申请或劳动者资格核验，不得填写联系方式、雇主、精确地点、证明材料或真实敏感个案。

不要求提交完整身份证、完整劳动合同、完整工资单、银行卡、家庭住址、企业内部文件或他人信息。无法或不愿核验者仍可提交普通意见，不因拒绝非必要材料而失去表达机会。

---

## 四、劳动者可以检查什么

- 能否用自己的话理解条款；
- 是否符合真实工作经历和劳动流程；
- 能否识别剥削、歧视、不公平、信息不对称和权力失衡；
- 是否尊重劳动者选择、申诉、协商和参与技术治理的权利；
- 是否可能被管理者拿来要求服从、加班、自我牺牲或承担技术成本；
- 是否遗漏某些行业、岗位、就业形式或特殊风险；
- 是否能处理工资、工时、监控、考核、裁员、社保、安全、职业病、算法管理和技术替代；
- 表达是否过于抽象、口号化或需要专业知识才能使用；
- 能否转化为对现实有帮助、风险透明的 AI 行为。

## 五、结构化评价

评分只用于发现问题，不评价劳动者本人，也不与专家评分相加。

| 分值 | 含义 |
| --- | --- |
| 0 | 完全不满足本维度目标 |
| 1 | 有严重问题，需要大改 |
| 2 | 一部分有用，但仍需明显修改 |
| 3 | 基本可用，只需小改或补充 |
| 4 | 很清楚、贴近现实且有充分保护 |
| N/A | 与本人经历无关或无法判断 |

可能伤害劳动者的内容另用“重大风险”标记记录，不与 0 分混为同一概念。空白表示未回答，N/A 表示不适用或无法判断，二者都不得按 0 分处理。

建议维度：

1. 容易理解；
2. 符合真实劳动经验；
3. 覆盖关键现实问题；
4. 增强劳动者主体性和实际行动能力；
5. 识别权力不平等；
6. 防止被管理者反向利用；
7. 公平处理技术收益、成本和风险。

可以不打分，只回答开放问题。表达能力、写作格式或理论术语不会决定意见价值。

项目汇总时按条款和维度报告有效评分数、空白数、N/A 数、原始分布和中位数；评分很少或分歧明显时不使用均值或排名。分数只用于发现需要修改或核查的位置，不自动决定采纳、否决或“评审通过”。

## 六、八个基本问题

1. 你能理解这条原则吗？哪里难懂？
2. 它是否符合你了解的工作经历？
3. 它可能怎样帮助劳动者？
4. 它可能怎样被管理者或其他权力主体利用？
5. 它忽略了哪些现实问题或人？
6. 你建议保留、修改、拆分、合并还是删除？
7. 你会怎样说得更清楚？
8. 你是否愿意提供一个已经充分匿名的劳动情境？

---

## 七、经验的使用边界

- 一个人的经历可以揭示真实问题，但不能自动代表全行业；
- 项目应区分亲历、转述、推测和价值判断；
- 经安全处理的经验可以用于发现问题线索、提供原则修订的现实依据、设计评测场景、检验专家判断，以及揭示行业和制度差异；每种用途都须遵守参与者授权和可推广边界；
- 案例公开前删除姓名、企业、精确地点、工号、罕见岗位、具体时间等组合识别信息；
- 不要求参与者提交维权证据来证明自己“值得被听见”；
- 不联系雇主、平台、主管或同事核验，除非参与者在充分知情后另行明确同意；
- 涉及正在进行的劳动争议、报复风险或人身安全时，优先作为非公开风险线索，不直接公开；
- 项目引用或改写匿名案例时，应遵守参与者选择的公开范围。

---

## 八、辅助参与和无障碍

每轮正式评审至少实际提供一种不依赖 GitHub 的低带宽或辅助参与方式；未提供时不得宣布正式评审开放。可提供的方式包括：

- 只评一条或若干条原则；
- 通过文字访谈或口述方式回答；
- 由可信辅助者代录；
- 使用翻译或语音转文字；
- 分多次完成，不被要求一次填完；
- 要求项目先用通俗语言解释问题。

代录、翻译或整理后的内容必须由参与者确认。辅助者不得替参与者选择结论、添加经历或改变观点。项目应在轮次总结中公开哪些辅助方式实际可用，不能把尚未提供的服务写成已提供。

---

## 九、选择参与者与代表性

定向邀请应尽量覆盖不同：

- 行业和岗位；
- 正式、派遣、临时、平台和灵活就业关系；
- 在职、失业、退休和职业转换状态；
- 地区和工作环境；
- 受算法管理、自动化、监控和安全风险影响的类型。

项目不得按意见是否支持现稿筛选。参与不足或某些群体缺席时，应公开缺口，不用少数参与者声称形成整体共识。

为避免反向识别，公开统计中的小规模敏感组合原则上不单独披露；具体阈值应在轮次公告中说明。

---

## 十、参与负担与回报

每轮招募前应说明预计所需时间、是否有补贴及其标准。当前项目不承诺报酬、岗位、资金、股份、代币或未来收益。若未来提供补贴，同轮同类工作应采用公开一致的标准，不得根据意见内容或赞同程度支付。

---

## 十一、安全、退出与反馈

- 不应在工作设备、单位网络或他人可见环境中提交可能带来报复风险的信息；
- 不公开真实单位、精确岗位、主管、同事、客户和家人信息；
- 发现误发隐私时立即按 [SECURITY.md](../../SECURITY.md) 报告，不在公开页面补充；
- 可以要求更正、停止联系或删除非公开个人信息；
- 可以在本轮关闭前撤回未公开意见；
- 已公开内容可能被复制或分叉，项目会处理可识别风险，但不能保证从所有第三方副本中完全收回；
- 正式劳动者意见按 [REVIEW_RESPONSE_POLICY.md](REVIEW_RESPONSE_POLICY.md) 获得回执、理由化反馈和程序复核机会。

严厉批评、低分、拒绝署名或不会使用规范语言都不是无效理由。冒充、重复操纵、骚扰、伪造经历或故意暴露他人隐私可以被标记为无效。
