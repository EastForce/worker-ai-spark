# 评审反馈与意见处理规则

> 状态：公开讨论稿  
> 版本：v0.2-draft  
> 本规则规定如何登记、判断、反馈、公开和复核意见，不承诺所有普通公开评论都获得长篇个别回复。

---

## 一、两套状态分开记录

原工作方案中的状态同时包含流程进度和实质决定。为避免混淆，公共台账使用两个字段。

### 1.1 流程状态

| 状态 | 含义 |
| --- | --- |
| 已收到 | 已生成编号，尚未完成初审 |
| 隐私暂停 | 发现可能的个人信息、安全或报复风险，暂不公开 |
| 待补充 | 缺少版本、条款、理由或必要核验信息 |
| 有效正式评审 | 内容有效，且正式身份核验完成 |
| 普通公开意见 | 内容有效，但未申请或未完成正式核验 |
| 未核验非公开意见 | 内容有效但未完成正式核验，且参与者未授权逐条公开 |
| 审议中 | 正在核实、对照或拟定决定 |
| 暂缓 | 依赖其他研究、人员、版本或安全条件 |
| 已撤回 | 参与者按规则撤回 |
| 重复合并 | 与同一参与者或同一来源的既有记录合并 |
| 无效 | 符合提交规则中限定的无效条件 |
| 已关闭 | 已给出当前版本的处理结果 |

### 1.2 处理结果

| 结果 | 含义 |
| --- | --- |
| 已采纳 | 主要建议已进入明确版本 |
| 部分采纳 | 只采纳部分内容，并说明边界 |
| 进入下一版本 | 原则上认可问题，但不在当前版本处理 |
| 需要补充材料 | 无法完成实质判断，等待材料 |
| 需要专项研究 | 需要额外事实、法律、技术或劳动场景研究 |
| 争议未决 | 合理意见冲突，当前不伪造共识 |
| 暂缓处理 | 有明确暂缓原因和重新检查条件 |
| 未采纳 | 已完成判断但不同意修改 |
| 超出项目范围 | 问题不属于本项目或本轮范围 |
| 无法核实 | 关键事实目前无法合理验证 |
| 无效提交 | 符合无效条件，不进入实质判断 |

流程状态和处理结果可以组合。例如“已关闭 + 部分采纳”“暂缓 + 需要专项研究”。“进入下一版本”必须有目标版本或重新检查日期，不能成为无限期搁置。

原工作方案中的“需要进一步讨论”统一映射为“争议未决”；如缺少事实、法律、技术或劳动场景材料，则使用“需要专项研究”或“需要补充材料”，避免同一含义出现多个统计口径。

### 1.3 成熟度/证据状态

成熟度与单条意见的处理结果分开记录，可使用：维护者草案、流程试评审、证据不足、完成双轨评审—争议未决、完成双轨评审—可继续修订、稳定使用（仍可重新评审）。“已合并”“多数支持”或“已收到若干评审”不是成熟度。

“完成双轨评审”是流程完成状态：第二轮及以后，须满足 [GOVERNANCE_AND_ROLES.md](GOVERNANCE_AND_ROLES.md) 的双轨人数、回避和记录门槛，但不表示参与者同意结论。“完成双轨评审—可继续修订”表示四名评审者已经完成对被冻结旧稿的审阅，但根据意见产生的新文本尚未由他们复看确认。“稳定使用”是更高的证据状态：除完成双轨流程外，四名独立轨道评审者还须复看拟生效版本的最终 diff、commit 和 SHA-256，均不得留下尚未回应的事实、基本权利、安全、严重伤害或关键适用范围异议，两个轨道并确认主要反对意见已被准确处理。存在此类实质异议时只能标为“完成双轨评审—争议未决”。

## 二、初审

收件后依次检查：

1. 是否存在隐私、安全、报复或第三人风险；
2. 是否能识别被评版本和条款；
3. 是否在本轮范围；
4. 是否为重复、补充或多渠道副本；
5. 是否包含足以理解的意见和理由；
6. 申请正式身份者是否完成必要核验；
7. 公开与许可选择是否明确。

隐私检查先于内容评价。对观点的赞同程度不得影响核验和有效性判断。

---

## 三、决定依据

决定不采用简单多数票。处理者应综合：

- 可核验事实与来源质量；
- 法律、研究和技术判断的适用范围；
- 真实劳动经验及其可推广边界；
- 对劳动者权利、生活和主体性的影响；
- 不同行业、地区和就业形式差异；
- 少数群体的特殊风险；
- 低频但严重的伤害可能；
- 与其他原则的一致性和冲突；
- 是否能形成可执行、可解释和可评测的要求；
- 是否存在被强势主体反向利用的可能；
- 修改本身会产生的新风险。

决定人必须能说明“为什么”，不能仅写“多数同意”“专家认为”或“劳动者支持”。

---

## 四、双轨处理

- 专家意见和劳动者意见使用不同轨道、不同维度和分开统计；
- 不把两类评分相加为总分，不以专家身份赋予固定加权；
- 每条重大修改的决定记录应分别概括两个轨道；
- 一人兼具双重身份时，同一原则、同一轮只按其声明的主要角色计入一个轨道；另一视角可以作为叙述性补充，但不增加另一轨道人数；
- 专家普遍认可而劳动者集中指出难懂、失真或可被滥用时，条款不得仅凭专家认可标为稳定；
- 劳动者提出重大问题但缺少专业分析时，状态应为“需要专项研究”，并邀请相关领域参与。

结构化评分只用于定位需要审查的维度，不自动决定采纳、否决或成熟度。空白表示“未回答”，N/A 表示“不适用或无法判断”，二者都不得按 0 分处理。每个轨道按条款和维度分别公开有效评分数、空白数、N/A 数、原始分布和中位数；样本很少或分歧很大时不使用均值或精确排名制造稳定结论，也不跨轨合并分数。

## 五、重大风险暂停门

以下风险一经具体提出，相关条款先标记“重大风险待核查”，不得在核查前称为稳定：

- 身份暴露、劳动报复或个人信息泄露；
- 生命、安全生产、职业健康或严重人身伤害；
- 歧视、强迫、羞辱或削弱基本权利；
- 虚构法律、事实或高风险建议；
- 以保护劳动者为名剥夺劳动者选择和主体性；
- 明显可被管理者、平台或项目用来扩大控制。

协调人应在收到具体风险后 2—3 个工作日内完成初步分级：确认是否限制公开、暂停相关条款或启动安全事件流程，并通知可联系的提交者。初筛只决定临时措施，不决定风险不存在。

风险标记不是自动永久否决。解除暂停必须同时满足：至少一名具有相关劳动经验的正式劳动者和一名相关正式专家分别完成核查，且两人均未参与原条款起草、原决定或本次风险初筛，并无重大冲突；风险事实和受影响群体得到回应；必要的文本、流程或安全措施已经落实；剩余不确定性、复发触发条件和责任人已记录；两名核查者均针对同一拟生效版本书面确认解除条件已经成立。任一核查者认为风险仍未处理，或任一条件不满足时，保持“重大风险待核查”或“争议未决”，不得因排期、票数或维护者单独判断解除。

## 六、正式意见反馈内容

每份可联系的正式专家或劳动者评审原则上获得：

- 不公开的随机回执编号和目标版本；
- 项目对意见的准确摘要；
- 流程状态和处理结果；
- 采纳的部分与对应修改位置；
- 未采纳、暂缓或无法核实的主要理由；
- 使用的事实、来源、已授权公共记录子项编号或无法反向识别的内部证据摘要；
- 专家与劳动者意见的关联或冲突；
- 利益冲突、回避和程序局限；
- 尚存争议与后续轮次安排；
- 可申请复核的期限和方式。

同一表包含多个条款时，反馈必须按 I01、I02 等子项分别给出流程状态、处理结果和修改位置，不能用一个总状态掩盖“部分条款采纳、部分未采纳或暂缓”。

如果摘要可能改变原意，应先请提交者确认。内部身份信息和其他参与者的非公开意见不得写入回复。

## 七、服务时限

| 环节 | 正常目标 |
| --- | --- |
| 收件回执 | 3 个工作日 |
| 重大风险初步分级与临时措施 | 2—3 个工作日 |
| 隐私、范围与完整性初审 | 7 个工作日 |
| 补充期限 | 通知后 10 个自然日 |
| 审议超过 15 个工作日 | 至少发送一次进度更新 |
| 正式个别反馈 | 本轮截止后 30 个工作日 |
| 轮次总结 | 个别反馈完成后 15 个工作日 |
| 复核申请 | 决定送达或公布后 10 个工作日 |
| 复核答复 | 完整申请收到后 20 个工作日 |

这是志愿项目的服务目标，不是虚假保证。能力不足时应暂停新收件或公开延期原因、新日期和未处理数量，不能保持“开放”却长期无回应。

隐私泄露、人身安全和报复风险不等待普通排期，先限制访问并启动事件响应。

## 八、普通公开、非公开和正文不署名意见

项目不承诺对每条普通公开评论单独长篇回复，但必须：

- 给公开 Issue 和 Discussion 合理标签或状态；
- 在轮次总结中反映主要问题、代表性异议和数量；
- 对导致实质修改的意见建立决定记录；
- 不因无法联系匿名者而把意见排除；
- 不把未核验的非公开或正文不署名意见计为正式核验人数；
- 不从写作风格推断或公开猜测匿名者身份。

## 九、复核

任何持有私密回执编号的提交者，或能够提供公开贡献链接的参与者，都可以就下列事项申请一次程序复核；不以正式身份核验为前提：

- 公开规则没有被执行；
- 意见被误引、漏掉关键内容或归错版本；
- 决定依赖明显事实错误；
- 存在未披露的重大利益冲突；
- 出现足以改变判断的重要新证据；
- 无效、重复或身份核验结论明显有误；
- 发生隐私、安全或报复风险。

单纯不同意结论可以作为下一轮新意见，但不必然启动程序复核。涉及事实错误、误引、版本归类、无效认定、利益冲突、隐私或安全的纠正请求不因参与者身份较低而被拒绝；要求重新判断原则实质内容的，按实质复核处理。

复核步骤：

1. 通过非公开渠道提交随机回执编号、原决定和复核理由；公开贡献者可提供公开链接。轮次提供辅助或口述参与时，也必须接受辅助填写的复核申请，并由申请人确认记录；
2. 记录员确认是否完整；
3. 由未参与原决定、原核验或原无效认定的人复核；涉及实质性原则判断时必须同时取得一名独立正式劳动者与一名独立相关正式专家的书面视角，两人均不得参与原条款起草、原实质审阅或原决定，并且无重大冲突；任一独立视角无法取得时保持暂缓并披露限制；
4. 结果为维持、纠正、重新评审、发回处理或执行隐私措施；
5. 公开匿名化结果和对原记录的更正，不静默覆盖历史。

没有独立复核人时，应披露限制并暂缓，而不是由任何参与原处理的人假装独立复核。个人信息查阅、更正、删除和安全请求不受 10 个工作日复核期限限制。

## 十、公开与版本修订

核心原则的实质修改应通过 Pull Request 或等效的可追踪版本差异完成。每次修改在 [DECISION_LOG.md](DECISION_LOG.md) 记录：

- 改了什么、为什么；
- 依据的意见编号和证据；
- 未采纳意见及理由；
- 回避与复核；
- 尚存争议；
- 生效版本。

公开数量必须把正式核验专家、正式核验劳动者、未核验公开意见、未核验非公开意见作为互斥主分类，并分别报告撤回、重复和无效。署名、化名、正文不署名和仅内部处理是主分类的公开方式属性，不得再次相加为参与人数。非公开意见只报告无法反向识别的聚合；小规模组合可能造成身份识别时，应合并类别或不披露细分。

## 十一、纠错

处理记录发现错误时：

- 保留原记录并追加更正日期；
- 说明错误是什么、由谁发现和对决定有何影响；
- 必要时重新通知受影响参与者；
- 重新计算公开统计，但保留旧版本可追踪；
- 不用删除历史掩盖程序错误。
