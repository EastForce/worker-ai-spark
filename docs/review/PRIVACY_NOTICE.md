# 评审参与者隐私说明

> 状态：公开讨论稿 
> 版本：v0.2-draft  

本说明适用于《劳动者AI基本原则》的专家/劳动者参与申请、邀请、身份核验、正式评审及相关联系。普通 GitHub 公开参与还受 GitHub 平台规则和公开互联网传播特性的影响。

---

| 项目 | 当前状态 |
| --- | --- |
| 个人信息处理者或责任主体名称/称呼 | 待填写 |
| 隐私权利请求联系方式 | 待填写 |
| 隐私负责人 | 待填写 |

| 数据存储服务、地区和备份机制 | 待填写 |
| 获授权访问的角色及人数 | 待填写 |
| 受托服务商及其用途 | 待填写 |

| 生效日期与适用轮次 | 待填写 |

仓库现有 workeraiopen@foxmail.com 仅明确用于安全问题报告。在项目另行确认、完成本表并说明服务商和跨境等事项前，不默认将其用于报名和身份核验。

## 二、最重要的安全提醒

- 不要在 GitHub Issue、Discussion、Pull Request 或代码仓库提交联系方式、证件或工作证明；
- GitHub 用户名不是匿名身份；
- 删除公开页面不一定删除通知邮件、缓存、分叉仓库、克隆和历史记录；
- 只提交完成评审所需的最少信息；
- 涉及正在进行的劳动争议、报复或人身风险时，先去除可识别信息，不要上传原始证据；
- 误发敏感信息时，立即使用 [SECURITY.md](../../SECURITY.md) 公布的安全渠道报告，不要在公开页面继续说明。

## 三、处理目的与信息范围

| 信息类别 | 示例 | 目的 | 是否公开 |
| --- | --- | --- | --- |
| 评审正文 | 对原则的意见、评分、理由、建议 | 评审、修订、反馈和争议记录 | 由参与者选择 |
| 申请信息 | 参与范围、可用时间、支持需求、候选池选择 | 处理申请、安排轮次和提供参与支持 | 否；另行授权的宽分类除外 |
| 联系信息 | 邮箱或其他可联系渠道 | 回执、补充、反馈、权利请求 | 否 |
| 宽分类背景 | 专业领域、行业、劳动类型、大致经历 | 确认评审轨道和披露覆盖缺口 | 仅匿名聚合或单独授权 |
| 核验信息 | 公开主页、推荐、遮挡材料、简短核验 | 确认参与类别和减少冒充 | 否 |
| 利益冲突 | 起草、任职、资助、商业或争议关系 | 回避和解释意见背景 | 只公开必要类别 |
| 授权与同意 | 公开范围、许可、未来联系、同意版本 | 证明和执行参与者选择 | 否 |
| 操作记录 | 私密回执编号、状态、访问和删除日期 | 审计、去重、响应和问责 | 默认不公开；只发布安全的匿名聚合 |

项目不得把这些信息用于广告、商业画像、招聘筛选、信用评价、向雇主报告、训练身份识别系统或与本评审无关的目的。

## 四、原则上不收集

- 完整身份证正反面或其他完整证件；
- 人脸、指纹、声纹等生物识别信息；
- 银行卡、金融账户和完整工资流水；
- 账号密码、访问令牌和安全凭据；
- 精确家庭住址；
- 与评审无关的医疗、家庭和私人生活信息；
- 未满 18 周岁参与者的身份核验材料；
- 单位商业秘密、内部保密文件和未经授权的通信；
- 能够识别同事、主管、客户、家人或其他第三人的材料。

参与者误发多余材料时，项目应停止不必要处理、通知替换并尽快删除。

---

## 五、同意和分项授权

项目以参与者在充分知情后的自愿、明确选择为基础处理非公开信息。以下事项不得捆绑：

- 参与本轮评审；
- 处理联系和核验信息；
- 在确有必要时处理可能属于敏感个人信息的材料；
- 公开姓名或公开称呼；
- 公开专业或劳动背景；
- 公开单位；
- 公开本人已完成正式专家或劳动者轨道核验的状态；
- 公开完整正文；
- 公开经确认的匿名化摘要；
- 按 CC BY-SA 4.0 发布公开贡献；
- 为后续轮次继续联系。
处理目的、方式、类别、保存期限、服务商或公开范围发生实质变化时，应重新告知；依法需要重新同意或单独同意的，应在继续处理前取得。

核验应优先采用公开资料、推荐或实时查看后不留存。遮挡后的劳动合同、工资、社保等材料仍可能包含敏感信息，只有在目的具体、确有必要、低风险方式不足并采取严格措施时才考虑，并应另行告知必要性和可能影响。

## 六、数据分离与访问

信息分为三个数据域：

1. 公共评审正文和台账；
2. 私密联系方式、授权和身份映射；
3. 临时核验材料。

三者先通过不公开、不可推导的随机回执编号关联。只有参与者另行授权公开且通过反向识别检查后，才生成另一套公共记录编号。公共仓库不得存放私密回执编号、身份映射或内外编号映射。

最低安全要求：

- 只授予已登记角色最小权限；
- 身份核验员和内容决定者尽可能分离；
- 开启服务商可用的多因素认证；
- 记录访问、导出、更改和删除；
- 禁止复制到个人聊天、公开云盘或其他未经批准的服务；
- 角色退出、设备丢失或轮次结束时复核并撤销权限；
- 备份、回收站和邮件附件纳入删除计划；
- 每轮结束由隐私负责人登记删除完成日期和未完成原因。

如果现有人员或技术无法满足这些要求，应停止正式核验，只接受不含身份材料的普通意见。

## 七、保存期限

以下为默认上限；法律另有要求或正在处理安全事件时，只保留必要部分并记录理由：

| 数据 | 默认保存期限 |
| --- | --- |
| 现场或实时核验内容 | 原则上不录音、不录像、不留完整对话 |
| 原始核验附件 | 核验完成后 7 个自然日内删除 |
| 待补充的原始核验附件 | 最长 30 个自然日；无回应后删除 |
| 涉及核验复核的附件 | 复核结束后 7 个自然日内删除 |
| 特殊争议确需保留的附件 | 书面记录必要性，且不晚于本轮结束后 12 个月 |
| 联系方式 | 个别反馈完成后 90 个自然日内删除；同意后续联系者最长 12 个月后重新确认 |
| 核验最小状态记录 | 轮次总结发布后 12 个月，之后删除身份映射并只保留匿名聚合 |
| 未公开评审正文 | 轮次总结发布后 12 个月内删除或不可逆匿名化，除非另行取得档案保存授权 |
| 访问、授权和删除记录 | 轮次总结发布后 12 个月 |
| 已授权公开内容 | 作为公共版本历史持续保存；受公开许可和平台复制限制 |

实际开放公告可以采用更短期限，不能未经重新告知任意延长。

## 八、参与者的选择与请求

参与者可以请求：

- 查询项目是否持有其非公开个人信息；
- 获取相关信息和授权选择的副本；
- 更正错误的联系方式、分类或授权；
- 撤回基于同意的后续处理；
- 删除已无必要、超过期限或违法处理的信息；
- 停止后续轮次联系；
- 解释身份核验和无效认定；
- 对处理决定申请复核；
- 报告隐私、安全和劳动报复风险。

权利请求渠道尚待开放前填写。项目应验证请求者与相关私密回执编号的关联，但不得要求其在公开页面粘贴编号，也不得为响应请求而重新收集过量身份信息。

撤回同意不影响撤回前已经完成的合规处理。已经公开并按开放许可传播的内容可能被第三方保存；项目不能保证删除所有副本，但应处理仍由项目控制的可识别信息，并在安全或法律风险下发布更正、去标识化或停止继续使用。

## 九、公开内容与匿名化

公开前至少检查：

- 姓名、联系方式、账号和证件；
- 单位、门店、班组、精确地点和罕见岗位；
- 具体日期、争议事实和其他组合识别线索；
- 第三人信息；
- 元数据、附件文件名、图片背景和文档属性；
- 小样本统计能否反推出个人。

公开统计中的敏感组合人数过少时，应合并类别、扩大时间范围或不披露。匿名化摘要如可能改变原意，应在公开前让可联系参与者确认。

## 十、安全事件

发现未经授权访问、误公开、丢失或泄露风险时，应：

1. 立即限制访问和暂停相关收件；
2. 不在公开渠道扩散敏感细节；
3. 保留调查所需的最少日志；
4. 评估涉及信息、人员、时间、复制范围和现实报复风险；
5. 采取删除、撤权、换密钥、去标识化等措施；
6. 及时通知可能受影响的参与者，说明可采取的保护措施；
7. 按适用法律判断是否需要向主管部门报告；
8. 发布不暴露个人的事件复盘和制度改进。

安全问题使用 [SECURITY.md](../../SECURITY.md) 公布的渠道。

---

## 十一、第三方服务与跨境

GitHub、邮箱、网页表单、云存储和通信工具可能由第三方提供，也可能涉及境外服务器、接收方或备份。

在正式收集非公开个人信息前，项目必须公布实际使用的服务商、存储地区、处理目的、数据类别、保存方式和参与者行使权利的路径，并完成适用法律要求的评估、告知和同意。未完成前不得把“技术上能收到邮件”当作已经具备合适的私密核验能力。

公开 GitHub 贡献意味着内容面向全球可访问；参与者不应在公开贡献中放入其不希望全球传播的个人信息。

---

## 十二、未成年人

当前阶段不开展未满 18 周岁者的正式身份核验，不收集其身份材料。未来如确需开展，应先发布专门规则并完成监护、必要性和安全评估。

## 十四、版本变更

变更处理目的、公开范围、信息类别、保存期限、服务商或境外提供安排时，应记录差异、生效日期和适用轮次。变更不得追溯扩大参与者此前的授权。
